# Design

## Context

动机见 `proposal.md`。当前代码已实现两行中文日期标签，但用户确认将最终输出改为 Python 赋值片段及中文金额说明。`format_positions_report` 已接收最新状态和下一交易日；`LatestPositions` 目前只有源日期、数量及现金，读取函数尚未提取 `total_value`。工作簿的 `portfolio_value` 已有该列，语义为包含现金的模拟总资产，无需修改生产该文件的回测及导出器。

## Goals / Non-Goals

**Goals:**

- 让日期、目标仓位和模拟总资产可按赋值片段复制，并让中文金额说明与配置金额使用同一数据来源。
- 保持数据读取、格式化、命令入口和文档一致，扩展失败验证而不产生部分输出。

**Non-Goals:**

- 不新增工作簿列、日历请求、依赖或旧格式开关，不计算实时账户资产或根据标的价格重新估值。
- 不将整段输出声明为可直接执行的 Python 文件；末尾“现金”和“总市值”是人工核对信息。

## Decisions

### 1. 从同一市值记录传递现金与总资产

在 `LatestPositions` 增加必需的 `total_value` 字段，并更新所有构造调用。读取函数保持一次打开工作簿、按最大数量日期选择源日期的流程，将市值表中该日的 `cash` 和 `total_value` 一起提取并验证有限数值。缺列、缺同日记录或无效总资产都产生可展示的摘要错误，不提供零值默认或其他日期回退。

选用工作簿的 `total_value`，而非重算标的市值或仅以现金代替，因为用户需要的是回测已记录的模拟总市值。该字段包含现金，不能再额外加一次现金。

### 2. 在现有格式化边界生成赋值片段

第一行使用 `state.source_date` 输出 `SIGNAL_DATE = dt.date(...)`，第二行使用已查询的 `next_trade_date` 输出 `TRADE_DATE = dt.date(...)`。年月日取整数属性，不补零；不使用系统日期，也不重新查询日历。

第三行输出 `TARGET_QUANTITIES = {`，筛选正数量后按原列顺序逐项生成四空格缩进、双引号代码、冒号后一个空格、整数数量及末尾逗号，最后用单独一行 `}` 闭合。已有 QMT 代码校验继续防止非法代码进入配置片段。无正仓位时保留开始与结束两行，不改为单行 `{}`。

随后依次生成 `TOTAL_VALUE = ...`、`现金: ...`、`总市值: ...`。总资产只做一次按分舍入及两位小数格式化，将同一个结果复用于 `TOTAL_VALUE` 和“总市值”，现金沿用既有半入到分规则。正常输出不带代码围栏、导入语句、空行或额外标题，命令仍一次性写出完整字符串并以换行结束。

### 3. 区分复制用配置与人工核对信息

`dt` 按用户指定保留为日期模块别名，输出不增加 `import datetime as dt`；调用方复制前半部分时自行提供该别名。通过字典闭合后的 `TOTAL_VALUE` 行界定配置片段，末尾中文两行用于核对。既有逐行 `代码: 数量`、中文日期标签和 `cash:` 格式不再同时提供，避免多种布局混在输出中。

例如格式如下，实际日期、代码、数量和金额均从当前工作簿及日历获取：

```text
SIGNAL_DATE = dt.date(2026, 10, 16)
TRADE_DATE = dt.date(2026, 10, 19)
TARGET_QUANTITIES = {
    "159650.SZ": 400,
    "159941.SZ": 21800,
    "159981.SZ": 11800,
    "512800.SH": 118400,
}
TOTAL_VALUE = 250000.00
现金: 10000.00
总市值: 250000.00
```

## Risks / Trade-offs

- [旧消费者依赖先前日期标签或逐行数量文本] → 文档明确新布局，使用完整字符串断言验证变量名、引号、缩进、逗号、行序和两位小数。
- [误将“总市值”解释为不含现金的标的市值] → 明确两处总资产都来自同日 `total_value`，添加总资产与现金不同的测试数据，不进行重复加总。
- [缺少总资产仍打印部分配置] → 先校验全部数据和日历再格式化，验证缺失/无效总资产时 stdout 为空。
- [无持仓或一位月日漏测] → 覆盖空字典七行输出、零负仓位过滤、一位月日及跨年日期。

## Migration Plan

先扩展具名状态与同日总资产读取，再替换格式化布局，更新相关构造调用、错误场景测试及 README。旧版两行日期标签虽已实现，本次修订使相关任务重新进入未完成状态。使用临时工作簿和固定日历验证，保持用户工作簿及原有代码修改不被本次规划流程覆盖；下游按新配置片段适配，无需数据迁移。
