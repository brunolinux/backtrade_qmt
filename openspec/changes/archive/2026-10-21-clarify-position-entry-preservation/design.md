# Design

## Context

`strategy_common.normalize_positions` 接收候选与当前持仓，返回新外层映射；当同一标的股数相同、入场时间不同，才用当前记录的入场价和时间替换候选对应字段。两个策略都调用该函数。v2 的保留持仓筛选直接复用止损计算后的 `Position` 记录，因而筛选后紧接的修正调用无效；调仓函数则可能在股数不变时改写入场信息。参见 proposal.md 和对应增量规范。

## Goals / Non-Goals

**Goals:**

- 让公共函数名说明“股数未变时保留原入场信息”的语义，并更新直接调用方。
- 简化 v2 每日决策步骤，同时保持调仓后的修正、交易记录生成和三张回测结果表的内容与顺序。

**Non-Goals:**

- 不修改持仓筛选、止损、调仓、收益计算规则或 `Position` 字段。
- 不顺带移除旧策略中类似的筛选后调用，也不整理工作区已有的其他改动。

## Decisions

1. **原函数改名，保留原签名和函数体。** 使用 `preserve_entries_for_unchanged_quantities(candidate_positions, current_positions)`，更新 `strategy_common.py` 内引用、两个策略的导入与调用，以及相关测试。旧名称不保留别名，避免两个名称长期表达同一行为。替代方案是在旧函数外增加包装器，但会扩大维护面并模糊唯一入口。
2. **仅删除 v2 保留持仓筛选后的修正调用。** 筛选结果中的每个记录均直接来自 `stopped_positions`，新旧股数和入场时间必然相同；修正函数在此只复制一次字典。保留筛选后的交易记录计算和调仓后的修正调用，以维持退出、调仓记录的阶段顺序。替代方案是删除所有修正调用，但调仓在股数未变时可能更新入场时间和价格，会改变后续盈亏基准。
3. **以现有行为回归测试验证。** 更新旧名称的测试引用，并运行公共状态转换、两个策略和 v2 回测的现有测试；针对重复调用、输入保护、未变数量修正及回测输出检查结果。无需为单纯删除无效调用编写与实现同构的新测试。

## Risks / Trade-offs

- 直接导入 `normalize_positions` 的外部代码会失效 → 在提案和规范标明破坏性重命名；迁移时改用新名称，参数顺序和关键字名称不变。
- 误删调仓后的修正会改变入场基准 → 仅删除 v2 筛选后的调用，并用回归测试核对不变数量、交易记录及回测输出。
- 工作区目前有其他未提交改动 → 实施时只编辑本变更涉及的行，避免覆盖或顺带提交那些改动。

## Migration Plan

将直接调用方从 `normalize_positions` 改为 `preserve_entries_for_unchanged_quantities`；无需迁移持仓数据或配置。若需回退，恢复函数名和调用处即可。
