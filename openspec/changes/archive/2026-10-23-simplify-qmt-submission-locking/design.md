# Design

## Context

参见 `proposal.md`。目前只有 `refresh` 调用 `_submit`：它在进入时用 `state.running` 拒绝并发或重入的定时调用，并在各阶段用 `sell_attempted`、`buy_attempted` 标记一次性提交。`_submit` 在调用 `passorder` 之前登记委托 ID，三个交易回调仅按该 ID 查询并报告结果。

## Goals / Non-Goals

**Goals:**

- 使锁的用途与实际同步边界一致：锁仅保护定时提交入口和阶段状态转换。
- 保持委托登记、同步异常处理、回调匹配与仅尝试一次的行为。

**Non-Goals:**

- 不改变 QMT 下单参数、时间阈值、固定计划或成交后的处理策略。
- 不据此推断 QMT 保证单线程回调，也不把 `passorder` 的调用返回视为委托成功。

## Decisions

### 将去重串行化保留在 `refresh`

保留 `state.running` 的加锁检查和设置，使同一时刻只有一个 `refresh` 进入计划提交循环。保留阶段标志的加锁设置，确保每阶段只启动一次。相较于在每一笔 `_submit` 再加锁，这一边界直接覆盖当前唯一调用路径，也防止阶段执行交错。

### 委托登记和回调查询直接访问 `attempts`

`_submit` 保留委托 ID 存在性检查，并在调用 `passorder` 前登记记录；`_callback_order` 保留账户和备注过滤，然后直接读取对应记录。登记发生在外部调用前，允许 QMT 在调用过程中立即触发回调。这里不把锁延伸到 `passorder`，避免回调重入时等待提交方持有的锁。保留 `attempts` 映射，因为回调仍需关联本策略计划。

### 使用现有回归测试验收

核对定时器并发及重入、同步回调、重复刷新、同步异常和单笔失败后继续的测试。行为未发生变化，不增加仅检查是否存在 `with state.lock` 的结构性测试。

## Risks / Trade-offs

- 若将来新增直接调用 `_submit` 的入口，现有“唯一入口由 `refresh` 串行化”的前提不再成立 → 新入口必须复用同一入口控制，或重新设计原子去重边界。
- QMT 的回调调度时序由客户端控制 → 保持先登记后调用，并用同步回调测试覆盖最早到达的回报。

## Migration Plan

无数据迁移。实施时只核对工作区现有改动与上述设计一致，再运行 QMT 定向测试及项目完整测试；若需回退，仅恢复 `_submit` 和 `_callback_order` 对 `attempts` 的同步访问，不调整 QMT 配置。
