# Design

## Context

动机见 `proposal.md`。`strategy_momentum_v2.backtest` 在每日调仓前调用旧盯市函数，新增持仓时单独以买入价初始化 `prev_close`。旧函数使用带符号的 `qty` 和 `close` 价差累加权益，再原地更新持仓的价格基准；当日无行情时跳过，缺少基准时使用当日价格。

首轮记账模块及兼容入口已经实现，原 8 项任务均已完成。当前 v2 仍从旧策略导入公共函数，记账模块的 `_read_close` 则重复了 `getv` 的读取逻辑。用户已删除 `momentum_util.py` 和 `momentum_v3.py`，后续实现以现存两个策略为来源，不恢复或依赖这两个文件。

现有 `getv` 遇到重复日期取最后一个值，读取失败返回 NaN。现有测试使用 `unittest`，可用本地合成行情验证，无需 tushare 或 QMT。

## Goals / Non-Goals

**Goals:**

- 记账计算可在相同输入下重复调用，输入持仓、行情及基准均不被修改。
- 状态推进与计算分离，但策略使用统一入口固定顺序。
- 通用模块不导入任何策略模块，保持现有调用路径和数值语义。
- 两个策略共享一份公共函数及 Trade 类型，彼此不再直接导入；记账模块复用同一份 getv。

**Non-Goals:**

- 不建立账户类、现金流水或通用持仓类型体系。
- 不纠正旧版价格口径、无效行情传播或组合导出问题。
- 不恢复已删除的文件，不统一两个策略各自的信号、选股、持仓保留和回测编排。

## Decisions

### 1. 使用普通函数与标的映射隔离策略数据结构

新增 `portfolio_accounting.py`，核心接口拟定为：

- `calc_mark_to_market_equity(quantities, current_close, prev_close, prev_equity)`：返回权益，不修改任何输入。按 quantities 的顺序，对具有当日价格的持仓计算 `qty * (current - previous)`；缺少 previous 时回退到 current。
- `update_close_marks(current_close, prev_close)`：仅将调用方准备好的价格快照写入 `prev_close`，不计算权益、不清理其他键。
- `update_equity_close(df_all, pos, prev_close, time, prev_equity)`：统一收盘结算入口，保持旧签名和返回权益的约定。提取持仓数量和仅含当日有行情持仓的价格快照，先计算权益，再推进价格基准。

核心只依赖数量与价格映射，不读取信号或 ATR；统一入口负责兼容旧 DataFrame 和 `pos[sym]['qty']`。相比把旧函数整体搬走，这样明确了副作用边界；相比设计一套账户类型，映射接口避免扩大本次范围。

### 2. 每次结算只读取一次当日价格

统一入口构造一份有序快照供计算和更新共用，避免两个步骤各自读取行情。删除记账模块内的 `_read_close`，从 `strategy_common` 导入 `getv`，使用 `getv(df, time, 'close')` 构造快照，保留既有浮点转换、重复日期取末值和读取失败返回 NaN 的语义；不再维护第二套读取实现，也不从策略模块反向导入。

该入口只承诺正常输入下的既有结果兼容，不提供数据库事务、异常中途状态回滚或跨调用的按日去重机制。直接调用核心更新函数时，调用者负责先计算、后更新；策略代码统一走结算入口。

### 3. 提取公共策略函数并保持单向依赖

根目录新增 `strategy_common.py`，从现存 `strategy_momentum.py` 提取以下实现，保持参数、返回值、数值口径及副作用：

| 公共部分 | 内容 |
| --- | --- |
| 行情与指标 | `getv`、`atr`、`calc_corr_matrix` |
| 数量与风险 | `calc_quantity`、`calc_position_size`、`calc_leverage_by_vol` |
| 持仓与记录 | `update_stop_price`、`update_portfolio`、`update_trades`、`update_portfolio_info`、`Trade` |

`Trade` 随交易记录函数迁移，确保新模块无需反向依赖旧策略，旧导入路径暴露相同类型。`calc_corr_matrix` 和 `calc_quantity` 虽未被 v2 函数直接调用，但属于其现有导入名称，也统一迁入并保留兼容出口。

`preprocess`、`calc_buy_pos`、`update_reserve_pos` 在两个策略中的规则不同，各自保留。旧策略的 `check_correlation_constraint`、`calc_buy_signals`，以及 v2 的 `rank_factor` 和两个 `backtest` 也保留在各自文件中。

依赖方向为：

```text
strategy_momentum ----> portfolio_accounting ----> strategy_common
         |                                              ^
         +----------------------------------------------+
strategy_momentum_v2 -> portfolio_accounting
         |
         +---------------------------------------------> strategy_common
```

公共模块只依赖标准库及现有 pandas、numpy，不导入策略或记账模块。两个策略直接从公共模块导入所需函数，通过模块级导入继续暴露旧公开名称。相比将公共函数全部塞入记账模块，该分层让指标与风险工具有独立归属；相比恢复已删除的工具文件，新文件以当前两个策略的实际公共部分为范围。

### 4. 保留结算兼容入口

`strategy_momentum.py` 通过导入或薄封装通用 `update_equity_close` 保留旧导入路径；旧版 backtest 因而也复用同一入口。v2 继续直接从记账模块导入该入口，其余公共依赖改为直接从 `strategy_common` 导入。

不删除旧入口，因为这会破坏已存在的调用者；不只在 v2 拆开调用两个函数，因为每个调用方都手工维护顺序容易产生零收益错误。

### 5. 兼容性验收以可手算样例和合成回测为准

- 前权益 1000，A 持仓 100 股由 10 涨至 11，B 持仓 50 股由 20 跌至 18，最终权益仍为 1000，两个基准推进至当日价。
- 纯计算重复执行结果一致，所有输入不变；仅更新基准时不改持仓和行情。
- 空仓、零数量、带符号数量、当日无行情、缺少基准、未持有标的和残留基准键保持旧语义。
- 停牌期间不推进基准，恢复行情后按最后估值价计算累计价差；新增仓位沿用买入价初始化基准，次日计算后续盈亏。
- 共享 getv 保持重复日期取末值与 NaN 传播，避免借重构引入行情修复；结算中的权益与基准仍使用同一次价格读取。
- 旧导入路径与新入口结果和副作用一致；用迁移前固定的最小 v2 合成回测样例比对 portfolio、curve、trades 的值、索引与列结构。
- 公共函数以迁移前固定的合成样例验证 ATR、相关矩阵、数量取整、仓位规模、杠杆率、止损更新、调仓、交易记录和组合信息的输出及副作用。保留既有 Trade 字段、顺序和旧导入兼容性。
- 分别在新进程中独立导入公共模块、记账模块和两个策略，验证导入顺序不会形成循环依赖，且无需已删除文件。

## Risks / Trade-offs

- [调用者颠倒计算和更新顺序]：策略只调用统一入口，文档及测试明确核心接口的先后约束。
- [浮点累加或 NaN 语义变化]：保留持仓遍历顺序和现有标量累加，不改成向量化求和或过滤无效值。
- [公共模块反向引用导致循环依赖]：将 Trade 与公共函数一起迁移，禁止公共模块导入策略或记账模块，以独立进程验证导入顺序。
- [提取时改变策略行为]：只移动公共实现及调整导入，保留策略专有函数，以固定数值样例、既有交易记录测试和回测基线验证。
- [覆盖已有工作区修改或恢复用户删除的文件]：以当前现存实现为提取源，保留 Trade 等已完成变更，尊重用户删除操作。

## Migration Plan

1. 保留首轮已完成的记账实现、测试及任务记录，以当前工作区为公共逻辑提取基线。
2. 固定公共函数的数值与副作用样例，新增 `strategy_common.py` 及 `tests/test_strategy_common.py`，迁移公共函数与 Trade。
3. 调整两个策略的导入并保留兼容出口；删除 `_read_close`，由记账模块调用共享 getv。
4. 执行 `.venv/Scripts/python.exe -m unittest discover -s tests`，对比固定回测输出并检查各模块独立导入；无需下载行情或写出业务 CSV。
5. 如需回退，只恢复本轮提取前的公共定义和导入；保留首轮记账功能、其他工作区修改和用户删除操作。不涉及数据迁移。
