# Design

## Context

动机见 `proposal.md`。已检查的工作簿包含 `portfolio_qty` 与 `portfolio_value`，日期列名为 `datetime`；前者没有现金，后者有 `cash`。`backtest_report.py` 已提供 QMT ETF 代码规则，`money.py` 已提供按分四舍五入。现有测试使用 unittest、临时 Excel 及 openpyxl 读回。

项目已声明 pandas、openpyxl、tushare 和 dotenv。`update_tushare.py` 从环境加载 `TushareToken` 并使用可选 `TushareIP` 地址，但不应通过导入该更新脚本来获取日历。交易日历会涉及认证、网络和未来日期覆盖范围，因此需要明确失败边界并使测试可离线执行。

## Goals / Non-Goals

**Goals:**

- 将工作簿读取、日历查询、纯文本格式化和命令入口分开，形成容易验证的小函数。
- 在全部数据准备成功后一次性输出，便于用户复制清单。
- 保持脚本导入无网络、无控制台输出和无文件写入。

**Non-Goals:**

- 不建立通用日历服务、持久缓存或多市场适配层。
- 不修改现有 Excel 写入器、回测策略或项目打包结构，不读取实时账户资金。

## Decisions

### 1. 独立单文件脚本，以具名结果连接各阶段

新增 `print_latest_positions.py`，包含读取最新状态、查询下一交易日、格式化摘要及 `main`。最新状态用轻量不可变具名记录表达源日期、有序的代码/数量对及现金，避免调用者依赖匿名元组位置。函数使用中文 Google 风格 docstring。

默认工作簿相对 `__file__` 定位到 `data/output_v2/backtest_results.xlsx`；提供 `--workbook PATH` 参数，显式相对路径按调用方当前目录解析。默认从其他工作目录启动仍能定位项目输出。此独立消费者无需把脚本职责加入 `backtest_report.py`，也不必为几个函数新建包。

### 2. 一次打开工作簿，按日期键连接数量与现金

用 pandas ExcelFile 和 openpyxl 引擎在同一次打开中读取两张表，日期按日解析；验证日期有效且各表内日期唯一。最新日期取数量表日期的最大值，不取末行，也不根据系统当前日期筛选。市值表按这个日期查找唯一现金，不要求两张表的最后一行一致。

最新数量记录保留原列顺序。复用既有 QMT 代码规则检查列名，并要求原代码已带正确后缀；不静默改写输入代码。检查最新记录中的全部数量为有限、整数及 100 的倍数后筛选大于零项，因此非法负数或缺失值不会因为过滤而被忽略。按原契约，无标的列但有日期仍是合法全现金记录。现金必须有限，允许为零或负数，使用既有半入到分规则显示。

不重新运行回测、不加载基金名称映射，不计算现金差额；现有工作簿是唯一仓位来源。

### 3. 复用 Tushare 交易日历，明确有界查询

命令入口从项目根目录 `.env` 加载配置且不覆盖已有环境变量，复用 `TushareToken`。`TushareIP` 配置存在时沿用现有 DataApi 地址设置方式；未设置时保留 Tushare 默认地址，不用空值覆盖。配置及客户端初始化只在实际运行命令时发生，不新增依赖，不导入 `update_tushare.py`。

通过 `pro.trade_cal(exchange='SSE', start_date=..., end_date=..., is_open='1')` 查询源日期次日至源日期后 31 个自然日，显式请求必要的 `cal_date`、`is_open` 字段。对返回日期解析、开市状态、请求范围及严格晚于源日期条件过滤，取最早值，不假设接口顺序。31 日为有界查询策略：窗口内无可确认开市日就明确失败，不扩展为无界重试。

采用现有 Tushare 而非新增日历库或固定工作日计算，复用项目配置并处理法定休市；代价是命令需要有效认证及网络。实现中日历客户端可注入，纯日期选择逻辑可用固定表测试，不依赖测试运行当天或真实接口权限。

接口依据：[Tushare 交易日历](https://tushare.pro/document/2?doc_id=26)。未来日历未公布或接口数据不完整时，不假定某个自然日必然开市。

### 4. 固定文本输出，失败不产生半份清单

格式化函数只返回完整字符串：第一行日期，随后 `代码: 整数`，最后 `cash: 两位小数`，不附标题、源日期或基金名称。命令入口先读取、验证、查询及格式化，再一次写入 stdout 并以换行结束；全现金时只有日期和现金两行。

可预期错误统一写 stderr 并非零退出，stdout 为空。日历适配器将认证和网络异常转为不含凭据的简洁消息，避免直接输出请求、配置或第三方原始异常；第三方调用产生的 stdout 不得混入清单。文件异常保留定位文件、工作表、日期或标的所需的信息。相比边读取边 print，这样不会在查询失败后留下看似完整的持仓片段。

## Risks / Trade-offs

- [日历服务不可用或尚未覆盖未来日期] → 明确失败，测试覆盖空结果与接口异常，不用自然日或工作日猜测。
- [数量与现金日期错配] → 两表按同一个最大源日期精确连接，拒绝重复日期或缺失现金。
- [用户修改工作簿后出现歧义或非法数据] → 读取时校验日期和最新状态，拒绝静默补零、截断或覆盖用户文件。
- [依赖真实 API 导致测试不稳定] → 固定日历结果与注入客户端用于单元及命令集成测试；真实网络不作为测试前提。

## Migration Plan

这是新增只读入口，没有数据迁移。先落地读取与格式化测试，再实现日历适配和命令入口，最后在 README 记录默认命令、`--workbook`、环境配置、样例及失败语义。完整测试使用临时工作簿，不能重写仓库已有结果文件。回滚只需移除新增入口及文档，原回测输出继续可用。
