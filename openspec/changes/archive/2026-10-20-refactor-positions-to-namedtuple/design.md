# Design

## Context

动机与范围见 `proposal.md`。两个策略的持仓创建入口均为各自的 calc_buy_pos；旧策略比 v2 多一个 take 字段。公共模块已有 Trade(NamedTuple)，持仓工具目前先复制内部字典，再对 stop、qty、entry 和 entry_time 赋值。记账入口只读 qty，纯盯市计算则接收独立的数量映射。

现有五个测试文件使用完整或部分持仓字典作为输入；其中输入隔离测试通过修改返回记录字段或要求记录对象身份不同来验证复制。已有完整六天回测、关键字调用、交易表及 CSV 固定预期可作为迁移基线。当前主规范的输入保护场景允许直接修改内部记录，本次差异明确将该场景迁移为替换不可变记录，不改变其他业务场景。

## Goals / Non-Goals

**Goals:**

- 用统一的显式字段模型承载两个策略的持仓；只读函数无需了解不同策略的内部字典。
- 状态转换返回新的外层字典，字段变化通过替代记录表达，未变化记录允许安全共享。
- 沿用原数值和边界规则，仅改变持仓表示及相应类型、文档和测试。

**Non-Goals:**

- 不把外层字典变为不可变容器，不冻结行情或参数，不改造数量及价格基准映射。
- 不新增持仓模型模块、类型依赖、兼容转换器、字符串下标访问或动态字段扩展机制。
- 不重命名现有函数、参数、配置键或持仓字段，不全面重写旧策略的其他注释。
- 不顺带纠正调仓现金约束、全量旧股数盈亏、缺行情展示、排名或候选扫描规则。

## Decisions

### 1. 在公共模块定义单一 Position 类型

在 `strategy_common.py` 中与 Trade 并列使用 typing.NamedTuple，字段顺序固定为：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| qty | int | 带符号持仓股数 |
| side | int | 原持仓方向 |
| entry | float | 每股入场价格 |
| entry_time | pd.Timestamp | 入场时刻 |
| stop | float | 每股止损价格 |
| atr | float | 建仓时 ATR |
| take | float 或 None，默认 None | 旧策略每股止盈价格，v2 不使用 |

构造时统一使用关键字参数。前六个字段必填，take 位于末尾且唯一具有默认值；不为测试中的部分字典设计无意义的默认价格或时间。类型注解不承担运行时校验或数值转换，保留 numpy 数值、NaN 及原时间值的实际运算行为。

采用 NamedTuple 可与现有 Trade 保持一致，并直接使用属性及 `_replace`。TypedDict 仍允许字段赋值；冻结 dataclass 也可实现不可变记录，但本次用户已选择具名元组，无需引入第二种记录模型。两个独立持仓类型或继承层级会增加公共函数和测试的复杂度，采用可选 take 更适合当前唯一字段差异。

### 2. 外层新字典，内部不可变记录

读取改为 `position.qty` 等属性访问。计算变化使用 `position._replace(...)` 并将结果放入新字典；不能给属性或记录下标赋值。没有变化的记录可直接复用，筛选操作只需构造新的字典；即便为空，返回持仓映射的函数也不返回输入映射本身。

NamedTuple 的不可变性是浅层约束，因此模型只包含当前数值和时间字段，不添加列表或字典字段。外层 dict 仍可变，回测在自身局部 pos 上的 update 可以保留，不据此扩大到所有字典操作的函数式改造。不可变记录共享后，是否具有不同对象身份不再构成正确性约束；允许实现创建内容相同的新记录，但测试不强制其身份。

### 3. 逐条保持状态转换的原顺序和字段

| 位置 | 迁移要求 |
| --- | --- |
| 两个 calc_buy_pos | 构造 Position；旧策略传入原 take，v2 使用 None；保留旧策略过滤零股数和 v2 保留零股数的差异 |
| calc_stop_positions | 新 stop 仍为原 stop 与收盘价减 ATR 倍数的最大值；其余字段，包括 take，保持原值 |
| rebalance_portfolio | 保留 ATR 倒数预算、阈值、入场价与时间重置、预算不足裁仓及最终零股数过滤的顺序，每次字段变化创建替代记录 |
| 两个 select_retained_positions | 返回新映射，可共享记录；旧策略仍比较数值 take，v2 仍只按原止损和排名条件保留 |
| normalize_positions | 只恢复符合原条件的 entry 和 entry_time；使用候选记录替换这两个字段，保留候选的其他字段，包括 take |
| calc_trade_records | 只改字段读取方式，保留当日开仓、同入场时间、零旧股数等跳过条件及全量旧股数收益口径 |
| build_portfolio_snapshot | 保留所有行情标的、停牌零值和现金行口径，不把记录元组直接作为输出行 |
| calc_equity_close | 从 Position.qty 构造原数量映射，其余估值流程、一次读取价格、完整新基准及 NaN 传播保持不变 |
| 旧策略其他使用点 | 同步相关性约束持仓注解、调试打印和所有持仓属性读取；只遍历代码的逻辑保持原样 |

旧策略保留筛选的调用前提是记录具有数值 take；旧策略自身开仓入口保证这一点。不得将 None 自动变为无穷大或新增容错比较，因为这会引入新的策略规则。公共函数不依赖 take 是否设置，并应在替换其他字段时原样保留。

### 4. 迁移接口和文档，不提供混合记录兼容

持仓输入及返回持仓的类型使用 `dict[str, Position]`，元组返回中的持仓元素使用对应类型；必要的局部空持仓字典增加注解以表达记录类型。保持参数名、顺序、默认值和其他返回元素结构不变。公共工具和 v2 的 Google 风格 Args/Returns 同步说明类型、外层新字典与不可变记录共享；旧策略仅更新本次持仓相关说明。

不添加 dict 转 Position、双类型分支、旧字典访问兼容接口或显式拒绝字典的类型检查。历史字典输入不再是受支持契约；外部调用者应使用完整 Position 构造记录。`calc_mark_to_market_equity` 的数量映射及价格映射契约不受影响。

调用方迁移示例：

```python
position = Position(qty=100, side=1, entry=10.0,
                    entry_time=pd.Timestamp("2026-01-05"), stop=9.0, atr=1.0)
quantity = position.qty
next_positions = positions.copy()
next_positions[symbol] = position._replace(stop=10.0)
```

旧的 `position["qty"]` 改为 `position.qty`；旧的内部字典赋值改为替换外层映射项。只有旧策略构造持仓时额外传入原数值 take。

### 5. 以现有数值用例验证表示迁移

五个相关测试文件的持仓构造辅助函数改为提供完整 Position；不把只需 qty 的估值测试扩展成策略逻辑。原固定数值、三张回测表和 CSV 字节预期保留，内部记录的预期类型同步迁移。

将字段原地赋值及 assertIsNot(record, input_record) 改为两类验证：直接设置字段失败；对返回外层字典替换、增加、删除记录不会改变输入映射或保存的记录。覆盖 `_replace` 保留其他字段、take 默认值和显式值，以及止损、调仓、筛选、修正全过程不丢失 take；对 normalize_positions 尤其验证其保留候选的 take，而非整条替换为旧记录。

继续运行新关键字与原位置调用、空持仓、带符号数量、停牌、重复日期、缺基准、单次价格读取、NaN、阈值及预算不足裁仓用例；候选扫描与保留排名边界不变。不给新增类型引入持久化的纯文档测试或性能基准。

## Risks / Trade-offs

- [外部字典输入及字符串访问失效]：在提案标记 BREAKING，提供完整字段和属性、替换示例；仓库内持仓创建及消费同时迁移。
- [take 信息在重建记录时丢失]：优先以 `_replace` 保留未变化字段，增加旧策略全过程及候选字段保留测试。
- [误以为外层字典也不可变]：保留新外层映射契约，并独立验证增删和替换不会影响输入。
- [复制测试错误地约束记录身份]：以值不变、字段赋值失败及映射隔离替代内部记录必须复制的断言。
- [表示迁移顺带改变数值行为]：沿用固定手算结果、完整回测及 CSV 预期，审查预算裁仓和零股数处理，不增加数值类型转换。

## Migration Plan

1. 应用开始时运行现有测试，并确认工作区修改；当前已提交基线为 `7796b8d`，预期测试数为 61，如实施前有新增测试则保留并核对。
2. 定义公共 Position 及其契约测试，迁移公共工具、记账入口、两个策略和对应持仓测试；按任务进行验证。
3. 核对全部持仓读取与赋值、类型注解和文档，运行全套测试、独立模块导入及 OpenSpec 严格校验。
4. 无数据文件迁移、依赖安装或导出格式更新。需要回退时将本次模型、生产调用和测试差异一起恢复；不调整其他活动变更或既有数据。
