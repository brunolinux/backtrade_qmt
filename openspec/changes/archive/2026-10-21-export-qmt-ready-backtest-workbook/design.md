# Design

## Context

动机见 `proposal.md`。当前脚本在主入口内直接透视持仓、拼接名称并写出三份 CSV；名称与代码产生重复的 `symbol` 表头。现有 CSV 测试通过 AST 提取脚本语句，无法验证实际工作簿。项目使用 pandas，尚未声明 Excel 引擎依赖。

两个策略共享 `strategy_common.py` 和 `portfolio_accounting.py`。原始价可能有三位小数，现金又是内部持仓快照的一条记录，因此不能对整个 DataFrame 统一保留两位或统一转整数。现有持仓数量算法按 100 取整，但公共函数测试也包含非 ETF 的合成头寸。

## Goals / Non-Goals

**Goals:**

- 将报表构造与 Excel 写入分开，便于独立验证数值、代码和单元格格式。
- 在实际资金结果形成的位置统一金额精度，同时保留现有浮点 API 与 DataFrame 返回契约。
- 通过共享模块同时覆盖两个策略，保持信号价格与交易价格的既有分工。

**Non-Goals:**

- 不将全部行情与策略运算改为 Decimal，也不在 Position 构造器中强制所有市场头寸为整手。
- 不增加手续费模型、实盘指令生成或新的权益工作表；具体导出范围见规格。

## Decisions

### 1. 独立构造报表与写入工作簿

新增 `backtest_report.py`，提供纯报表构造入口和工作簿写入入口。构造入口接收持仓表、交易表和名称映射，复制并返回三张导出表；写入入口接收目标路径及这些表。`backtest_etf_v2.py` 只负责调用、保存到 `data/output_v2/backtest_results.xlsx` 并继续已有绘图。模块导入不触发数据加载或回测。

工作表固定为 `trade`、`portfolio_value`、`portfolio_qty`。交易名称列明确叫 `name`，代码列为 `symbol`，其余交易字段保留。两张持仓表保留日期索引；市值表保留现金并将 `total_value` 放在末列，数量表在数量校验前删除现金记录。空结果保留三张表及必要表头，不制造日期或交易。

采用独立模块而不是继续在主入口添加语句，避免测试依赖脚本 AST；不改变策略返回值，以免让报表格式影响策略接口。

### 2. 按十进制金额处理资金结果

新增无策略依赖的 `money.py`，集中金额舍入、按原始价计算金额和金额求和所需的最小辅助函数，供公共策略、记账和报表模块使用。使用 `Decimal(str(value))` 和 `ROUND_HALF_UP` 量化到 `0.01`；价格差、数量乘积在十进制域计算后再量化，避免先计算有误差的浮点表达式再包装。金额累加使用 Decimal 或整数分，在既有接口边界转回数值型 float。

不使用 Python `round` 的半偶舍入，不仅设置 Excel 格式，也不提前将每份原始价舍入到分。NaN 延续既有传播语义，不替换为零；非有限值处理不得引入新的量化异常或伪造有限金额。

舍入位置如下：

| 位置 | 计算规则 |
| --- | --- |
| 盯市权益 | 入参权益按分处理，每个标的的有符号数量乘原始价差形成按分增量，再按分求和 |
| 交易盈亏 | 原完整头寸数量乘原始退出价差，结果按分处理；退出原因仍按舍入前盈亏符号判断 |
| 持仓市值与现金 | 每个标的数量乘完整精度 raw_close 后按分处理；现金为按分权益减已舍入市值之和 |
| 资金分配 | 可用资金边界和实际占用金额按分处理；理论分配比例、风险距离、权重及目标数量公式保留精度 |
| 导出金额 | 校验并统一为按分数值；total_value 从已舍入明细与现金按分求和，保持与权益一致 |

`calc_position_size` 的价格比例、风险距离及信号计算不做金额舍入。价格基准字典继续记录原始三位价格。上述方案比只在导出时 round 更能保证内部现金一致性，也比把全部策略改为 Decimal 更能控制影响范围。

### 3. 在导出边界规范代码与数量

代码遵循 QMT 的 `代码.交易所` 约定，参考官方变量约定页面。当前 ETF 映射限定为六位代码 `15` 开头对应 `.SZ`、`5` 开头对应 `.SH`；已有正确后缀保持不变。未知代码、错误后缀及规范化后重复的标的列明确报错，不静默合并。名称映射与交易代码使用同一规范化规则，内部行情键不改名。

不导入带有实盘职责的 `qmt_passorder.py`。暂不抽象跨市场代码库，也不推断当前 ETF 范围之外的交易所。

数量先检查有限值、整数值及 100 的倍数，再转换整数数值类型；保留负号和零，拒绝缺失值、小数头寸和非整手头寸，不通过截断或填零修复。此检查限定导出边界，不破坏通用持仓函数接受其他测试头寸的能力。

### 4. 使用 openpyxl 写出带格式的数值单元格

在 `pyproject.toml` 声明 `openpyxl` 并更新 `uv.lock`。通过 pandas ExcelWriter 写出三张表，随后设置金额格式 `0.00`、数量格式 `0` 和日期格式。金额与数量保持数值单元格，代码保持字符串；交易表不额外写行号。选择 openpyxl 是因为其支持写入与读取验证，且当前环境已有该引擎；不引入另一个只用于写出的引擎。

测试读取实际临时工作簿，核对表名、列名、代码、数据类型、金额值与格式，而非依赖 Excel 的视觉显示。写入路径由调用方传入，支持临时目录测试。

## Risks / Trade-offs

- [资金舍入可能改变临界资金附近的后续数量] → 将舍入限定在实际资金边界，风险与信号中间量保持精度；增加半分、三位原始价和旧有整分基线回归。
- [浮点返回值仍有二进制表示误差] → 计算与累加在十进制域完成，边界返回 float 保持兼容；测试按金额语义比较，不能声称 float 内部十进制精确。
- [旧 CSV 消费者不兼容] → 明确新工作簿路径、表名和数量表无现金契约；停止生成旧 CSV，但保留磁盘上的历史文件。
- [代码规范化可能暴露旧数据中的异常] → 错误信息指出具体代码或冲突列，拒绝猜测交易所和隐式合并。
- [仅测 DataFrame 无法发现写入格式问题] → 用 openpyxl 读回工作簿，覆盖空结果、重复调用和输入不变性。

## Migration Plan

先加入金额辅助函数及回归，再接入公共资金计算；接着完成报表构造、引擎依赖与写入，最后替换脚本的 CSV 调用和对应 AST 测试。运行完整测试及 OpenSpec 严格校验，确认两种策略既有整分基线、原始价精度和输出一致性。

下游改为读取同一个工作簿中的三个工作表，并使用带后缀代码。回滚时还原相关代码与依赖即可恢复 CSV 路径；历史 CSV 无需恢复，生成的工作簿也不作为自动删除对象。
