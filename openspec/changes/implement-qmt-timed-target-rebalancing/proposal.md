## Why

当前回测报告已能输出目标仓位配置，但缺少与该配置配套的 QMT 定时执行脚本。参考脚本仍依赖行情订阅、动态重算仓位和买入资金估算，与已确认的固定计划、分时提交及失败后继续执行要求不一致，需要建立独立且可模拟验证的执行流程。

## What Changes

- 创建 QMT 内置 Python 脚本 `qmt_passorder.py`，使用 GBK 编码和标准库，通过手工复制的账户、日期、目标数量和模拟总资产配置运行。
- 初始化校验交易日期、账户资产和目标数量，根据初始持仓生成固定卖出及买入计划；模拟总资产不得超过实际总资产。
- 每 3 秒检查时间，首次超过 09:35:00 提交卖出计划，首次超过 09:36:00 提交买入计划，各阶段和各标的仅尝试一次。
- 使用交易所对应的即时成交剩余撤销市价委托，不订阅或读取行情，不预估买入资金，不因资金不足缩量或重试。
- 接入委托、成交及委托错误回调；逐笔报告结果、成交价格数量和可用费用信息，单个标的失败不阻断其余标的。
- 增加模拟 QMT 接口的本地测试，并同步执行说明。本次不接入真实账户、不实际下单，不修改回测及仓位报告输出。

## Capabilities

### New Capabilities
- `qmt-target-rebalancing`: 校验复制的目标仓位配置，生成固定计划，在指定时间提交 ETF 调仓委托并通过回调报告结果。

### Modified Capabilities

无。

## Impact

- 目标文件：`qmt_passorder.py`、`qmt_passorder.md`、新增的 QMT 执行模拟测试。
- 运行依赖 QMT 内置账户、交易日历、定时器及交易 API；无新增第三方 Python 依赖。
- `qmt_passorder_xxx.py` 仅作为参考，不修改用户保留的备份。当前目标脚本已被用户删除，后续实施时重新创建。
- 市价委托可能拒绝、部分成交或撤销；脚本报告结果，不保证达到目标仓位。每日独立启动，不提供进程重启后的持久化去重或跨日调度。
